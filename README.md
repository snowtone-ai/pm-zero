## これは何か

**pm-zero v12** は、Claude Code を使ったソロ開発を自律化するための **OSレベルのルールセット**です。

v12 は pm-zero の歴史で**初めて、引き算を主目的とした**リリースです。
v4.0 から v11.1 まで、ほぼすべてのバージョンが足し算でした。理由は単純で、**散文のルールを1行足すコストがゼロ**だったからです。書くのも維持するのも無料なので、増加に抵抗する力がどこにもありませんでした。結果、1429行——その運用者自身が把握できない仕様書ができあがりました。

**pm-zero は非エンジニアがハーネスを設計しなくて済むように存在します。**把握できない仕様書は、システム側の失敗です。

---

## v12 の唯一の憲法

> **設定値・スクリプトの終了コード・hook のいずれかとして書けないものは、pm-zero に入れない。**

これだけです。帰結は3つ、すべて意図的なものです。

- **散文のアドバイスは入場資格を失う。** チェックとして書けない教訓は、たいてい最初からルールではありませんでした。
- **品質の主張が反証可能になる。** 「設計は健全である」は v12 が主張できない文です。「`node scripts/verify.mjs` が 0 で終了する」は主張できます。
- **増加に再びコストが発生する。** 今後の追加は「書く」だけでなく「作る」必要があります。v4〜v11 に一度もなかった圧力です。

## v12 が根拠にした3つの発見

すべて公式ドキュメントと実測から確認したもので、推測ではありません。

**1. 長いセッションのほうが安い**
キャッシュから読んだ分は通常入力の**約10%**。Claudeサブスクではキャッシュは**1時間**保持されます。新セッションはこれをゼロから積み直すので、v11 の「1セッション1タスク」は毎回コールドキャッシュ税を払っていました。

**2. モデルとeffortの切り替えは、会話全体の再読み込みを起こす**
両方ともプロンプトキャッシュのキーの一部です。v11 のモデルルーティング表は、切り替えを無料だと仮定していました。
→ v12 では**セッション中は切り替えない**。深く考えさせたいターンは `ultrathink`（APIに送るeffortが変わらないのでキャッシュが生存）。別モデルは**サブエージェント**で（親のキャッシュを元々共有しないので追加コストなし）。

**3. 13の品質ゲートのうち7つは、原理的に作文でしか満たせない**
しかもその作文を書くのは、そのコードを書いた本人が同じ文脈のまま。
→ 18プロジェクトの実測が結論を出しています。**実行可能な `verify.mjs` は12個に定着し、13ゲートの判定記録は1つも残っていません。**

## 品質はどう担保されるか

```
scripts/verify.mjs   →  lint / typecheck / test / build
.github/workflows/   →  同じ4つを GitHub 上で実行  ← v12 唯一の追加
```

**v12 で唯一「足した」ものが CI です。**

違いは中身ではなく、**実行される場所**です。v11 では、マージしたいエージェントが、自分のマシンで、自分のセッションから検証を走らせ、結果を自分で報告していました。**エージェントはローカルの検証結果については「通りました」と報告できますが、GitHub のチェックは捏造できません。**

ブランチ保護でこのチェックを必須にすれば、マージ条件は「エージェントの自己採点」から「物理的な条件」になります。

## 失敗から学ぶ仕組み（v12で作り直し）

v11 の学習ループは**閉じていませんでした**。`docs/issues.md` に書き込む側は動いていましたが、**セッション開始時に読み返す対象に入っていなかった**からです。読み返されない記録は学習ではありません。

実測：18プロジェクト中、学習ルール（`.claude/rules/`）が実際に作られたのは**1つだけ**。`docs/issues.md` の13個のうち5個は空テンプレートのままでした。

v12 は、**意外な失敗が1回**起きた時点で、質問をひとつだけします。

```
機械が検出できるか？
  YES → verify.mjs にチェックを足す（+ バグなら再現テスト）
        完了。教訓はビルド失敗になり、誰も覚えておく必要がなくなる ← 既定
  NO  → .claude/rules/<領域>.md に予防手順（+ 由来の記録）  ← 最終手段
```

これは憲法を学習に適用したものです。**実行できる教訓は、読まなければならない教訓より価値がある。**忘れることも、圧縮で消えることも、飛ばすこともできないからです。

## セキュリティ：3層と、1つの受け入れたリスク

| 層 | 守るもの | 発火 |
|---|---|---|
| 1. `permissions.deny` | 秘密ファイル、破壊的gitコマンド | **全モード。hookより先** |
| 2. `guard.mjs` | コマンドの形、`.env.example` 例外つきの `.env.*` | 全モード・全サブエージェント |
| 3. OSサンドボックス | プロセスレベルで全部 | **ネイティブWindowsでは利用不可** |

v11 は「bypassモードでは hook だけが確実に発火する唯一の層」と書いていましたが、**これは誤りです**。公式ドキュメントは deny ルールが bypassPermissions を含む全モードで適用されると明記しています。**deny のほうが先に発火します。**

### 受け入れたリスク（見落としではなく、明記）

deny も hook も、**ファイルを自分で開くスクリプト**（`node -e`、`python -c`）には適用されません。公式の答えはOSサンドボックスですが、**サンドボックスはネイティブWindowsで動きません**（対応は macOS / Linux / WSL2）。

**このリスクは受け入れ、塞ぎません。** 個人の趣味プロダクトであり、本番システムも実際のお金も第三者データも、作業ツリー内の秘密情報もないためです。WSL2への移行コストは、守る対象の価値を上回ります。

重要なのは、**これが書き留められている**ことです。穴が塞がっていると思い込むことが失敗であって、開いていると知っていることは失敗ではありません。

```

├── CLAUDE.md                     ← 主指令。毎ターン読み込み
├── .claude/settings.json         ← 薄いプロジェクト設定
├── docs/
│   ├── vision.md                 ← プロダクトの北極星
│   ├── state.md                  ← 現在の実行ポインタ
│   ├── decisions.md              ← 意思決定ログ
│   ├── issues.md                 ← 「今」詰まっていることだけ（起動時に読む）
│   └── repo-map.md               ← ナビゲーション
├── tasks.md                      ← 唯一の実行台帳
├── scripts/
│   ├── setup.mjs
│   └── verify.mjs                ← lint / typecheck / test / build
├── .github/workflows/ci.yml      ← 同じ4つを GitHub で ★v12追加
├── HANDOFF-JA.md                 ← 完了・エラー報告（日本語）
├── .env.example
└── .gitignore
```

v11.1.1 の13ファイルから：`ci.yml` を**追加**、`docs/lessons.md`（何も読まない）と `AGENTS.md`（マルチベンダー時代の遺物）を**削除**。

## クイックスタート

> 前提: Claude Code、Node.js、pnpm、Git、ripgrep がインストール済み。

**Step 1 — グローバル設定（初回のみ）**
`~/.claude/settings.json`、`~/.claude/hooks/guard.mjs`、`~/.claude/CLAUDE.md`、
`~/.claude/agents/{planner,reviewer}.md` を配置。詳細は `pm-zero-knowledge-v12.md` §4。

**Step 2 — プロジェクトを作る**
```powershell
git clone https://github.com/snowtone-ai/pm-zero.git my-project
cd my-project
```

**Step 3 — 話しかける**
```
「〇〇というアプリを作りたい。ユーザーは〜で、目的は〜」
```
必要なことだけを一括で質問し、`docs/vision.md` と `tasks.md` を生成します。

**Step 4 — 任せる**
```
「では実装を開始して」
```
完了時に日本語のハンドオフレポートが届きます。

## よくある質問

**Q. 削った7つの品質ゲートが何かを拾っていたのでは？**
A. その可能性は残ります。ただし18プロジェクトを走査して、それらのゲートの判定結果が成果物として残っている例は**1件も見つかりませんでした**。証拠がないことは、ないことの証明ではありませんが、判断材料としてはこれが手元にある全てです。

**Q. Opusなしで品質は保てますか？**
A. レビューの価値の源泉は「実装の思い込みを引き継がない新規コンテキスト」であって、モデルの大きさではありません。v12 では Opus をレビューに使いますが、それは**サブエージェントのモデル選択が親スレッドに追加コストを課さないから**であって、Sonnet では不足だからではありません。

**Q. bypassPermissionsは危険では？**
A. 危険操作は deny ルールと `guard.mjs` の2層で遮断します（38ケース検証済）。ただし**プロンプトインジェクションには防御がありません**——これは公式ドキュメントが明記している事実で、v12 は受け入れたリスクとして記録しています。

**Q. なぜ v12 は機能を減らしたのですか？**
A. 減らしたのではなく、**入場条件を変えた**結果として消えました。憲法（設定値・終了コード・hook のいずれかであること）を通らないものが落ちただけです。同じ条件を通れば、いつでも戻せます。

## 設計思想

> *「会話は使い捨て、ファイルが記憶。実行できないルールは、ルールではない。」*

1. **ファイルシステムが唯一の真実の源泉** — チャット履歴が消えてもプロジェクトは続く
2. **教訓は、読むものではなく実行されるものにする** — ビルド失敗は忘れられない
3. **著者を検証者にしない** — CIの価値は人間不信ではなく、自己申告に情報量がないこと
4. **安全はプロンプトではなく設定とフックで** — 決定論だけが圧縮に耐える
5. **塞げない穴は、塞いだふりをせず書き留める** — 思い込みのほうが危険
